# KVMPanel 应用设计：副屏、KVM 网页与后端

日期：2026-11-20。来源：与用户的设计讨论，草图保存在 `.superpowers/brainstorm/`（不提交）。

## 1. 要做什么、为什么

KVMPanel 是用 T113-i 自制的小板，装在开放式机箱上（没有玻璃），同时做两件事：

- **副屏（Dashboard）**：一块 1080×1920 的 MIPI DSI 屏，带触摸。屏幕本身是竖屏扫描，用户决定横过来装（2026-11-22），方向可以在设置里改。实时显示这台电脑的硬件状态，还可以在屏幕上进入设置。数据由 PC 上的上位机程序通过 USB 发给板子。
- **IP KVM**：通过网页远程看画面、操作键鼠、控制电源、挂载镜像、开终端和管理文件。**基线是 NanoKVM 最新版（app 2.5.4，2026-11-10）的全部功能**。这里的意思是把这些功能都实现出来，不是和它比性能。HDMI 采集到的画面只在网页里显示，不上副屏。

这是个人兴趣项目，优先追求简单、能用。副屏的视觉效果是用户最在意的地方。

## 2. 目标、非目标和反目标

**目标**

- 副屏按第 4 节已定稿的样式实现，在板子上实测流畅度后选定 UI 框架。
- 网页的结构和交互参照 NanoKVM：控制台加设置窗口，另外新增「文件 / 终端」工作台。
- 网页同时承载整块板子的设置，副屏上的设置项在网页里都能找到。两边共用同一份配置，任一处修改都会同步。
- 后端自己重写，不移植 NanoKVM 的代码。

**非目标（这次不做）**

- H.264、H.265、WebRTC：T113-i 没有可用的视频编码器，只做 MJPEG。
- 上位机程序本身，以及上位机到板子的数据格式。这两样先不管，副屏先用模拟数据驱动。
- NanoKVM 里依赖它特有硬件的功能：OLED 屏、Wi-Fi 模块、PCIe 版的 HDMI 输出开关。PicoClaw 是 NanoKVM 外装的 AI 助手，也不算基线。
- 商业发布、合规和验收流程（见 `AGENTS.md`）。

**反目标（就算能跑也算失败）**

- 副屏看起来单调、像表格：用户明确要求要有动效和图表。
- 副屏只能用手点：所有设置都必须能用实体按键操作。
- 副屏和网页的设置各存一份，导致不一致。
- 改 USB 功能时绕过端点预算，把 USB 枚举搞坏。

## 3. 硬件条件和约束

板级接线根据 2026-11-22 导出更新。主控特性见 T113-i 数据手册。 [当前硬件说明](../../../hardware/README.md)

| 项目 | 情况 | 对软件的影响 |
|---|---|---|
| SoC | T113-i，双核 Cortex-A7，没有 3D GPU | UI 全部靠 CPU 软件渲染。显示引擎（DE）有硬件图层，可以做透明叠加 |
| 内存 | 单颗 DDR3 `K4B4G1646D`，512 MB | 后端、副屏和视频缓冲共用这 512 MB |
| 存储 | CARD1 microSD 接 SMHC0，当前版移除板载 SPI NAND | 系统、数据分区、镜像和共享盘的位置可配置 |
| HDMI 采集 | HDMI1 → LT8619C → 8 位并行 CSI（`CSI_D0..7`、`HSYNC`…）→ U18 | 视频格式和分辨率上限由这条链路决定，要实测 |
| USB0（OTG） | 连到 USB1（Type-C）和 JAF2，作为 gadget 接 PC | **硬件上只有 EP1–EP5 各一个 IN、一个 OUT**，FIFO 共 8 KB + 64 B（数据手册 USB2.0 OTG 一节）。改 kernel 也加不了端点 |
| USB1 | 接 USB-A U16，只能做 host | 用来接外设，不能当 gadget |
| 网口 | RTL8211F，RGMII，千兆 | — |
| 光线传感器 | BH1750 接 I2C（`I2C_SCL/SDA`，和屏幕触摸共用） | 自动亮度 |
| 按键 | BOOT、RST 直连 SoC，副屏实体键经 H7 的 KEY_ADC 接入 | 软件保持“上、下、OK、FN”四键，键值待按键板确认 |
| 电源控制 | H1/H3 前面板接口通过 GAQY212GSX 光继电器接入电源、复位和电源灯信号 | 电源和复位由 GPIO 驱动，主板 HDD 灯在 H1/H3 间直通 |
| 其他 | WS2812 灯珠、两个蜂鸣器、STC8G 辅助电源管理（`PWR_TX/RX`） | 这次不涉及 |

## 4. 副屏（已定稿）

### 4.1 主屏

对应草图 `e2-v5.html`。

- **背景（E2）**：深色底，上面有几团缓慢漂移的模糊色光，蓝、绿、紫三色。CPU 或 GPU 负载越高，色光越亮。**不画背景网格线**（2026-11-20 用户决定去掉）。
- **前景**：半透明的毛玻璃面板，带细描边和圆角。
- **没有时钟和日期**。边距压到最小，四个面板从上到下排列，按内容多少分配高度，铺满整屏。
  1. **CPU · Ryzen 9 9950X3D**：
     - 标题行右侧是**状态栏**，三个小标签：
       - `ETH`：网口速率和 IP。没插网线时灰色，插了网线但没拿到 IP 时橙色。
       - `PC`：通往电脑的 USB-C，同时承载上位机数据和 KVM 键鼠。两样都通时绿色，只通一部分时橙色，没连上时灰色。
       - `USB`：USB-A 口上插的设备名，没插时灰色。
     - 下面是 16 根核心负载柱，分成 CCD0（V-Cache）和 CCD1 两组。
     - 数值行：有效频率、BCLK、FCLK、Vcore、Tctl、占用（带进度条）、PPT。
  2. **GPU · RTX 5090**：Core 频率、温度、显存结温、占用（带进度条）、显存 xx/32 GB（带进度条）、功耗。
  3. **内存 · DDR5-6000 2×32G**：
     - 已用 xx/64 GB（带进度条）。
     - 内存温度合成一行，**只显示上位机实际上报的槽位**（比如这台电脑只有 `A2 / B2`），空槽位不显示，也不占位。下面是一张**比其他曲线大一些的温度走势图**，每个上报的槽位一条线。哪些槽位有内存由上位机的数据决定（2026-11-20 用户决定）。
     - MCLK / UCLK。
  4. **整机 · B850M AORUS ELITE ICE**：整机功耗、两块 SSD 的温度、网络上行和下行。**不显示风扇转速**。
- **每一行的格式**：`名称 | 小曲线 | 数值`，三列固定宽度。
  - 小曲线有细边框、深色底、两条淡网格线，曲线下方有面积填充。
  - 显示最近 60 秒的数据，**量程按每项固定**，不按数据自动缩放，否则 BCLK 这种平稳值会被放大成噪点。
  - **刷新方向从左往右**：最新的数据点在最左边，旧数据往右移出（2026-11-20 用户决定），大图表也一样。
- **超阈值**的数值会闪红。阈值在设置里调，默认 Tctl 85 °C。
- 参数项目按这台电脑来列，用 AMD 的术语。没有 P/E 核这类概念。

上面描述的是竖屏布局（屏幕方向为竖、竖（倒）时使用）。

### 4.1.1 横屏布局（1920×1080，2026-11-22 用户选定方案 B）

对应草图 `.superpowers/brainstorm/1795-*/content/landscape-offline.html` 中的 B。屏幕方向为横、横（倒）时使用。背景、面板样式、行格式、量程、刷新方向和闪红规则都和竖屏一样，只是排法不同：

- **三列**，宽度大约 1.1 : 1 : 1，铺满整屏，没有时钟和日期。
- **第 1 列 · CPU**：核心负载柱比竖屏高一倍左右，下面是和竖屏相同的数值行，列底部是一张 60 秒大图表，两条线：CPU 占用（0–100 %）和 Tctl（30–95 °C），各自按固定量程归一化，图例写明量程。
- **第 2 列 · GPU**：和竖屏相同的数值行，列底部是一张 60 秒大图表：GPU 占用（0–100 %）和功耗（0–600 W）。
- **第 3 列**：最上面一行单独放**状态栏**（ETH / PC / USB），保证它在屏幕右上角；下面依次是内存面板（含 DIMM 温度行和温度走势图）和整机面板。
- 曲线随列宽拉伸，名称列和数值列宽度固定。

### 4.2 上位机没连上时：显示 KVMPanel 自己的状态（2026-11-22 改）

取代原来只有转圈的等待画面。对应同一份草图的第二部分，竖屏、横屏各一版，文字英文。背景色光调暗、偏青色，亮度跟板子自己的 CPU 负载走，一眼能和数据主屏区分开。

- **顶部**：`KVMPanel` 和主机名，右侧是和主屏相同的状态栏。
- **大状态**，区分两种情况：
  - `PC is off`：电源灯输入（PE12）为灭。下面写最后一次收到数据是多久以前。
  - `Waiting for host app`：电源灯亮，但上位机没有数据；带转圈动画。下面写 USB 是否连通和最后一次收到数据的时间。
  - PC 关机时右侧有 **`⏻ Power on PC`** 按钮（触摸和按键焦点都可用），按一下等于短按一次电脑电源键（PE13 光继电器）。PC 开着时不显示这个按钮，避免误关机。
- **Remote access**：IP 用最大号字，下面是 `https://kvmpanel.local`，开了 Tailscale 时再加一行 Tailscale 地址。
- **Network · eth0**：链路速率和双工、板子网口自己的收发速率（两条 60 秒小曲线）、MAC。
- **KVM**：远程会话（人数、账号、来源 IP）、HDMI 输入（无信号时写 `No signal`）、视频流状态（帧率或 `Idle`）、挂载的虚拟介质、当前启用的 USB 功能。
- **KVMPanel · T113-i**：SoC 温度和 CPU 占用（小曲线）、内存（带进度条）、SD 卡用量、运行时间和软件版本。
- **底部**：息屏倒计时和 `FN · Settings` 提示。倒计时规则不变（设置里的“PC 离线后息屏”）；息屏后触摸或按键唤醒。
- **布局**：竖屏从上到下排列；横屏第一行是大状态（占两列）和访问地址，第二行是 Network、KVM、板子三列。

### 4.3 设置

触摸和实体按键都能操作。每一项都要有按键焦点，用蓝色描边表示；按键提示假设为 `▲▼` 选择、`OK` 确定、`FN` 返回。

- **显示**：
  - 自动亮度开关（BH1750）。
  - 亮度滑块，开自动亮度时变灰。
  - PC 离线多久后息屏（默认 5 分钟）。
  - **屏幕方向**（2026-11-22 新增）：横、竖、横（倒）、竖（倒）四选一，默认横。选横或横（倒）时用 4.1.1 的布局，选竖或竖（倒）时用 4.1 的布局，设置页和子页面也跟着转。触摸坐标随方向换算。在副屏上改完会立即生效，并弹出 10 秒的“保留这个方向？”倒计时，没按确认就退回原来的方向，防止触摸方向对不上时改不回来。网页上改方向不弹这个倒计时。
- **KVM**：
  - KVM 服务总开关，关掉后只保留副屏。
  - 访问地址，只显示文字，**不要二维码**。
  - 当前远程连接数。
- **Function 键**：短按、长按分别从这些动作里选：无动作、进入/退出设置、开关屏幕、切换亮度档位（低 → 中 → 高 → 自动）、暂停 KVM 远程。
- **USB 功能**：见 4.5。
- **系统**：设备信息、重启 KVMPanel、关机 KVMPanel（只关这块板子，不影响电脑）。

### 4.4 设置的子页面

风格和主屏一致。

- **Function 键 · 短按 / 长按**：单选列表。
- **KVM**：
  - 访问地址，`https://kvmpanel.local` 加 IP。
  - 当前状态：远程会话（人数、账号、来源 IP）、HDMI 输入分辨率、视频流帧率和码率、挂载的虚拟介质。
  - 操作：**重启 KVM 服务**、断开所有远程会话、重置 USB 键鼠、弹出虚拟介质。
- **设备信息**：主机名、软件版本、内核、运行时间、IP、MAC、链路速率、SoC 温度、内存、`/data` 存储、环境光读数。
- **关机 / 重启确认**：弹窗，默认焦点在「取消」。

### 4.5 USB 功能（副屏和网页各有一个入口，共用同一份配置）

把所有 gadget 功能都列出来，每项标明占用的端点。页面顶部是 IN、OUT 两条端点预算条，各 5 格，用满时变橙色。

| 功能 | IN | OUT | 默认 |
|---|---|---|---|
| 键盘（boot 协议，BIOS 里能用） | 1 | 0 | 开 |
| 相对鼠标（BIOS 里能用） | 1 | 0 | 开 |
| 绝对鼠标 | 1 | 0 | 开 |
| 合并两个鼠标（高级；开启后绝对鼠标不再占端点，个别 BIOS 不认） | 0 | 0 | 关 |
| 大容量存储（光驱、虚拟 U 盘、文件共享，做成同一功能下的多个 LUN） | 1 | 1 | 开 |
| 虚拟网卡（NCM 或 RNDIS） | 2 | 1 | 关 |
| USB 串口（ACM） | 2 | 1 | 关 |
| 上位机数据 | 0* | 0 | 开 |

\* 开着绝对鼠标时，上位机数据作为厂商自定义的 HID 集合挂在绝对鼠标接口上。PC 通过 EP0 的 SET_REPORT 写入，不占端点（`f_hid` 设 `no_out_endpoint=1`）。没开绝对鼠标时（相对鼠标要保持 BIOS 能识别的 boot 协议，不能挂额外的集合），上位机数据改用独立的 HID，自己占 1 个 IN。

- 如果打开某一项会超出预算，这一项会变灰。点它时，**端点预算条正下方会浮出一条小提示**，例如「端点已满 · IN 还差 1 个，先关掉其他功能」，2.5 秒后自动消失。**不要用弹窗**。
- 改完按「应用」才生效，生效时 USB 会重新枚举。应用前提示电脑上的键鼠会断开 1–2 秒，也可以撤销。

## 5. KVM 网页

### 5.1 控制台

对应草图 `kvm-web.html`。

- 远程画面铺满整页。顶部是可以拖动、可以自动隐藏的悬浮菜单栏，依次是：
  - 画面、键盘、鼠标、镜像、**文件 / 终端**、电源（带开机状态点）、WoL。
  - 状态区：分辨率、帧率、延迟，以及 NUM / CAPS / SCR 三个锁定键指示。
  - 设置、全屏。
- 每个菜单按钮都有下拉面板，内容按 NanoKVM 对应的功能来做（第 6 节）。镜像面板里显示 SD 卡的剩余空间。

### 5.2 设置窗口

左栏分两组：

- **KVM 组**（沿用 NanoKVM）：通用、键盘与鼠标、画面、镜像与共享。
- **系统组**：
  - 新增：副屏（屏幕方向、亮度、息屏、告警阈值、显示项勾选）、USB 功能、Function 键、存储（SD 卡）。
  - 沿用 NanoKVM：网络、Tailscale、账号与权限、MCP、更新、设备（主机名、SSH、mDNS、重置 USB 键鼠、重启 KVM 服务、重启和关机 KVMPanel）、关于。

### 5.3 文件 / 终端工作台

对应草图 `kvm-files.html`。

- 点菜单栏的「文件 / 终端」后打开工作台：**左边是终端，右边是文件管理器**，中间的分隔条可以拖动调宽度。原来单独的「终端」按钮合并进来了。
- 两种打开方式，在**设置 › 通用**里选，默认是页内浮窗：
  - **页内浮窗**：叠在远程画面上，可以拖动、缩放、最小化，标题栏里的「⧉ 新标签页」可以把它弹到独立标签页。另有开关可以记住浮窗的位置和大小。
  - **新标签页**：工作台占满整个标签页，布局不变。
- **终端**：支持多个标签页，第一个是 KVMPanel 本机的 shell，串口终端作为另一个标签页。
- **文件管理器**：
  - 根目录可以切换：**SD 卡、共享盘、系统 `/`**。用户决定保留系统 `/`。
  - 支持路径导航、上传（包括拖放）、新建文件夹。
  - 右键菜单：下载、重命名、删除、挂载为光驱、在终端中打开。已挂载的镜像有标记，底部显示剩余空间。

## 6. KVM 后端的功能范围

以 NanoKVM app 2.5.4 为准，减去第 2 节的非目标。

- **视频**：
  - MJPEG 流，分辨率跟随 HDMI 输入。
  - 可调画质、帧率上限、缩放方式。
  - 静止画面不发送（帧差检测，默认开），没有观看者时停止采集。
  - HDMI 信号状态，以及 EDID 编辑。
- **键鼠**：
  - 绝对和相对鼠标，触屏手势。
  - 粘贴文本、屏幕键盘、多种键盘布局、Ctrl+Alt+Del、自定义快捷键、Leader 键。
  - 防休眠鼠标抖动、锁定键状态回显、重置 HID。
- **电源**：电源键短按和长按、复位，电源灯和硬盘灯状态，操作前确认。网络唤醒（WoL）可以给设备起名字。
- **虚拟介质**：
  - ISO/IMG 可以挂载成大容量存储或光驱（ISO/UDF），默认只读。
  - 镜像来源：上传、URL 下载（可暂停和续传）、SHA-256 校验、格式校验。
  - 文件共享盘，同一时间只允许一个写入方。
  - 可选的虚拟网卡（NCM/RNDIS），MAC 地址固定。
- **终端**：本机终端（PTY）、串口终端、SSH 开关、自定义脚本。
- **网络**：DHCP 或静态 IP、DNS、HTTPS（自定义证书和端口）、mDNS、Tailscale、自定义监听地址。
- **账号**：
  - 登录，bcrypt 存密码，HttpOnly cookie。
  - 管理员和普通用户两种角色，权限可以细分；只读观看会话。
  - 防暴力破解（先延时，再锁定）。
  - 改密码后，旧会话立即失效。
- **管理**：
  - 在线和离线升级，升级包带 SHA-256 校验，可以自定义升级服务器。
  - 主机名、语言、页面标题和 logo。
  - 可选的看门狗、重启。
- **MCP**：用 API key 鉴权，提供截图和键鼠的远程 API。
- **副屏相关（新增）**：
  - 接收上位机数据，转发给副屏进程。
  - 统一管理配置，副屏和网页的设置都存在这里。
  - 按 4.5 节管理 USB gadget 的组合和端点预算。

### 7.1 内核和驱动适配（在这次范围内）

用户确认驱动适配也算在这次计划里，而且是主线：应用里贴硬件的部分都要等对应驱动可用后才能在板上验证。现状和差距见 `docs/linux-6.18.md`。需要补齐的驱动：

- **视频采集**：T113-i 并行 CSI，加上 LT8619C（HDMI 转并行）驱动，经 V4L2 输出。
- **JPEG 编码**：调查硬件编码路径；不可行时改用 libjpeg-turbo + NEON 软件编码。
- **屏幕**：TD4322 面板的 DSI 驱动（Command Mode + TE 同步），在 DTS 里加上面板节点，并接入背光控制。
- **输入**：S3508 参考触摸驱动，以及经 KEY_ADC 读取的实体键。
- **其他**：BH1750、光继电器电源控制 GPIO、USB0 gadget（configfs）、SD 卡（SMHC0）、THS 温度、看门狗，以及和 STC 的关机通信。

**板子还没到货，也还没上电过。**到货前，驱动工作只能做到能编译、能在 QEMU 或静态检查中验证，以及准备好 DTS 和板上测试步骤；真正的板上验证等到货后进行。microSD 冷启动待实板验证。

DTS、内核配置和补丁按 `AGENTS.md` 放在 `software/os/`，技术结论写进 `docs/linux-6.18.md`。

## 8. 验证方式

- **副屏**：先在 PC 上用各框架自带的模拟器（SDL 或桌面窗口）以 1080×1920 和 1920×1080 分别运行，再上板子实测；横屏要单独测 CPU 占用。对比原型的结论写进 `software/app/dashboard/README.md`。

## 9. 风险和待确认事项

- **MJPEG 编码**：主线 6.18 很可能用不上 T113-i 的硬件 JPEG 编码。如果只能用 libjpeg-turbo 加 NEON 软件编码，1080p 估计只有十来帧，要实测。
- **采集链路**：LT8619C 的 8 位输出加上 T113-i 并行 CSI，1080p60 的带宽可能不够，可能只能跑 1080p30 或更低。主线 6.18 对 T113-i CSI 的支持也要确认。
- **SD 卡**：SD 接口在 PF0–PF5，由 VCC-PF 供电。SD 卡默认用 3.3 V 信号，改板时要确认 VCC-PF 的电压。
- **SET_REPORT 通道**：上位机数据走 EP0 的 SET_REPORT，要在 Windows 上实际验证 hidapi 写入，以及 `f_hid` 的接收路径。
- **按键**：KEY_ADC 的键值映射等按键板实测后确定。
- **端点和 FIFO**：5 个端点各配 512 B FIFO，正好吃满 8 KB 的 FIFO 预算，不能再细分。
- **横屏的旋转开销**：屏幕按竖屏扫描，横装时每帧都要由 CPU 转 90° 再写进帧缓冲。主线的 sun8i DE 混合器不提供旋转，所以没有硬件可以分担。只重绘变化区域的框架（LVGL）受影响较小；整帧重绘的框架（Qt Quick 软件渲染）多一次整帧转置。等板子点亮后实测。

## 10. 审查后补充的决定（由 Claude 决定，用户可以推翻）

- **功能清单的边界**：第 6 节就是完整清单。它是根据 2026-11-20 对 NanoKVM 2.5.4 README、CHANGELOG 和 wiki 的调研整理的，没列出的 NanoKVM 功能这次不做，实现时不需要再回头去翻 NanoKVM。
- **遥测数据按数据驱动**：
  - 契约里传的是通用的具名指标：名称、单位、量程、阈值、分组。核心数、内存槽位、SSD 的数量和标签都来自数据本身。
  - 主屏布局（第 4.1 节）是针对这台电脑的一份布局模板，按指标名把数据放到对应位置；缺失的指标显示 `--`。
  - 上位机的真实数据格式以后再定，现在由 mock 生成器按 4.1 节的项目产生数据。
- **副屏框架怎么选**：
  - 先在 PC 模拟器上做三版主屏原型，交给用户看一次，由用户评判观感。
  - 用户选出的框架作为暂定，继续实现 4.x 的全部内容。
  - 等板子能点亮 DSI 屏后再实测性能；如果暂定的框架跑不动，再换。
- **升级和持久化数据**：
  - 在线和离线升级只替换应用包（`kvmd`、`panel`、网页静态文件），不动内核和根文件系统。
  - 配置、账号和证书放在单独的数据分区，挂载在 `/data`；镜像和共享盘放在 SD 卡上。数据分区位置由系统镜像决定，应用只认挂载点。
  - 整机镜像升级（A/B 分区）等系统层面稳定后再做。
- **串口终端**：
  - 串口设备做成可配置项，比如 `/dev/ttyS1`。板子上没有接到被控电脑的 UART 时，串口标签页就隐藏。
  - USB 串口（ACM）是另一回事：它是让 PC 把板子当成一个 COM 口，和网页里的串口终端无关。

- **屏幕方向怎么实现（2026-11-22，Claude 决定）**：
  - 考虑过三种：
    1. 由副屏程序按逻辑分辨率（1920×1080 或 1080×1920）绘制，在送进帧缓冲前转换方向，触摸也在程序里换算。这是选定的做法。
    2. 内核侧旋转（DRM plane 的 rotation 属性或 fbcon rotate）。主线 sun8i DE 不支持 DRM plane 旋转，fbcon rotate 只管控制台，所以不可行。
    3. 换一块原生横屏的屏。用户已经决定把现有的屏横过来装，所以不考虑。
  - 方向存在共享配置里（契约里 `panel` 配置新增 `orientation`，取值 0 / 90 / 180 / 270，默认 90，即横屏），副屏和网页都改这一份。
  - 横屏的 90° 和 270° 哪个是正的，要等实际装好后确定；默认值以后可以改。
- **离线页需要的数据**：板子自己的网口收发速率、SoC 温度、CPU、内存、SD 卡用量，以及 KVM 会话、HDMI 输入、视频流、虚拟介质、USB 功能的状态。panel socket 现有的消息里缺什么，就按“契约先行”补进 `panel.schema.json`，并在 mock 里生成。
- **已取消**：STC 固件在网页上传和刷写的功能，用户在 2026-11-22 提出后又取消了。
