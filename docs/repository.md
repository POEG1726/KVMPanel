# 仓库与版本管理

## 主仓库

根目录是本地 Git 仓库，默认分支 `main`。尚未创建或配置 GitHub/GitLab 等远程仓库。

自有应用、MCU 固件、DTS、配置、补丁、文档与小型证据进入主仓库。上游源码、大型导出、厂商私有包、缓存、日志、构建产物和凭据不进入主仓库。

开发分支使用 `codex/<topic>`，每个独立且通过相应检查的阶段做本地提交。初始提交使用明确的 Codex 本地身份；不修改全局 Git 身份。

## 上游仓库

`manifests/sources.lock.json` 是版本依据。`sources/repos/*.git` 为独立 bare 镜像，WSL 工作目录是独立克隆，不依赖原 C 盘研究目录的对象或 Git alternates。

当前采用浅历史、完整固定提交内容。要研究历史时明确 fetch/deepen 的范围；更新版本需同时更新锁文件、兼容性记录、补丁和验证结果。

在 WSL 上游仓库做改动时，先创建开发分支；随后将补丁导出到 `software/os/<component>/patches/`，避免只把唯一改动留在被主仓库忽略的工作目录。

## 产物与发布

每批镜像记录完整来源提交、配置、DTS、补丁、工具链、根文件系统、应用版本、SHA-256 和测试状态。`artifacts/` 仅是本地产物目录，建立目录不代表存在可发布镜像。
